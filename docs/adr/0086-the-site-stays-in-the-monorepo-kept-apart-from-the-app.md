# The site stays in the monorepo, kept apart from the app

The site, `apps/site` (ADR 0071), takes the Edition's tokens, Mascot, legal pages and Слово дня from the same repository as the app, through `@slovo/language-pack`, `@slovo/contracts` and `@slovo/ui/tokens`. A repository of its own would have to copy them or publish them as packages, and the site would drift from the app the day the design changed, the problem the Astro site was built to end. The price of sharing one repository is coupling: a change to the site waited for the app's Jest shards, the site could import a React Native component from `packages/ui` and break its static build, and a Dependabot or Expo update could move the site's Astro stack along with the app's.

**The site stays in the monorepo, and three checks keep it apart from the app:**

- **CI tests only the side a pull request can affect.** The `changes` job of `ci.yml` compares the pull request with its base. When every changed file belongs to the site (`apps/site/`, `editions/*/legal/`, `pages.yml`), the app's Vitest and Jest parts pass without running. When every changed file belongs to the app (`apps/mobile/`, `maestro.yml`, `ota-update.yml`), the site's tests do. Any other change, a shared package or an Edition's tokens among them, and every push to `main` run both. A part passes rather than being skipped, because the required check counts a skipped job as a failure. Lint, typecheck and the package boundaries always cover the whole workspace.
- **The site reaches no React Native.** Two dependency-cruiser rules: `site-imports-no-react-native` forbids the site to import `react-native`, `expo` or their packages, or the app; `site-reaches-no-app-or-ui-components` forbids it to reach the app or any of `packages/ui` but `tokens`, directly or through another package. The second is needed because the cruiser leaves `node_modules` out of its graph and cannot see React Native behind a workspace package.
- **The site's Astro stack is pinned exactly and updated on its own.** `apps/site/package.json` names exact versions of Astro, its integrations, Tailwind and the fonts, and Dependabot's `site` group brings their updates in a pull request apart from the app's. React and `react-dom` stay the app's, at the version the Expo SDK sets (the workspace override of `react-dom`): the site follows an Expo upgrade there, and its tests and build in that pull request show whether it still works.

## Considered Options

- **A repository of its own for the site**: rejected. It would copy the tokens, the Mascot and the legal pages, or need them published as packages, and double the CI, the ownership and attribution checks and the Dependabot set-up. It is worth reopening if someone outside the project builds the site, or if it grows into a product of its own with a blog or a CMS.
- **Workflow-level `paths:` filters**: rejected. A workflow that does not run leaves the required check missing, and the pull request cannot merge.
- **Turborepo's `--affected` for every job**: not taken now. It would change how every package is tested, not only the app and the site, for a saving this decision does not need.
- **An ESLint `no-restricted-imports` ban in the site**: rejected. It sees only the site's own imports, not React Native behind a workspace package, and the repository's boundaries already live in dependency-cruiser.
