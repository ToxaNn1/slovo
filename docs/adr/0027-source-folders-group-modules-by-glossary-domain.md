# Source folders group modules by glossary domain

The modules of `packages/core/src`, `packages/ui/src` and `apps/mobile/src` are grouped into folders named after the domains of `CONTEXT.md`, and the files inside a folder stay flat. A domain that has a folder in one of the three packages has a folder of the same name in every one of them where it appears, even with a single module, so everything about Collections lies in `saved/` in the Core, the UI and the app, and everything about the Game, the Daily Crossword included, in `game/`. A loose file at the root of `src/` is either the top or the shared base, and the root names each one; the rest of a package lives in its domain folders and in the package's own layers.

The rules:

- **One folder per domain, the same name everywhere.** A module of a domain goes into that domain's folder, even when it is the only one.
- **The Mix and Hidden Entries share `mix/`.** Hiding a Category and taking it out of the Mix are one and the same (`CONTEXT.md`, Hidden Category), and the folder also holds the Mix's chips, its Rarity Floor and the Rarity Test that sets it, which no Hidden Entry explains, while a Hidden Entry is one of the things the Mix leaves out. The Core's `entries/mix.ts` stays in `entries/`: the Entries module decides which Entries are Eligible (ADR 0015) and imports it, so in `mix/` it would make `entries/` and `mix/` import each other.
- **What stays at the root.** In the Core: `composition.ts` (the top, ADR 0018) with the tests of the whole composition beside it (`composition.test.ts`, `opened-from-notification.test.ts`, `opened-from-search-or-mood.test.ts`, `opened-from-widget.test.ts`); `ports.ts`, `in-turn.ts`, `local-date.ts`, `backend.ts`, `retry.ts`, `shuffled.ts`, `feed-notice.ts` and `user-state-schema.ts`, the shared base (`retry.ts` is the one rule by which every request to the backend is tried again, ADR 0064; `shuffled.ts` is the one shuffle of the Game Modes and the Rarity Test, which in `game/` would close the cycle `mix/` → `game/` → `knowledge/` → `mix/`; `feed-notice.ts` names the Feed Notices, which the user-state schema parses without importing `feed/`; `user-state-schema.ts` is the registry of the records each domain folder declares in its `records.ts`, so it sits above them all); `index.ts`, `testing.ts` and `test-support.ts`. In the UI: `index.ts` and `tokens.ts`. In the app: `composition.ts`; `opening.ts` and its gate `opened.tsx` (ADR 0036), which every domain opens through and the account screen draws over; `api.ts`, the backend's client the domains share; `keep.ts`, which four domains wait on; `shown.ts` and `shown-in-effect.ts`, what the reader is shown of the switched-off or hidden features, read by the routes, the Entries and Sync; `test-support.ts`; and the type declarations `env.d.ts` and `slovo-edition.d.ts`. Each package's `test-support.ts` holds shared test helpers, which `index.ts` does not export.
- **The packages' own layers.** The UI's `providers/`, `decor/` and `primitives/` sit below its domain folders and import none of them. The app's own are `device/`, the device code its adapters share; `foreground/`, which tells the shell when the app is in the foreground; `shell/`, what the root layout sets up before and around every screen (`lifecycle`, `launch-splash`, `intl-polyfill`), which only the routes import; and `diagnostics/`, the log and the crash reports with the scrubbing of personal data they share (ADR 0048), which import no domain. `foreground/` stays its own folder below the domains: the Feed, the Game and Sync import it, so inside `shell/`, which imports Sync, it would close a cycle; for the same reason `opening.ts` and `opened.tsx` stay at the root rather than in `shell/`. A device adapter sits in its domain, such as `device-share` in `share/`, and the app's config plugins sit in `apps/mobile/plugins/`, outside `src/`.
- **A module goes where its domain's rule lives, not where its name points:** `correction-mode` sits in `game/`, since it is a Game Mode built on the Game, and the Core's `haptics` too, since only the Game's haptic sequence uses it (ADR 0025), as does the app's `game/haptics.ts`, the device's haptic motor; `content-update/language-pack.tsx`, which opens the downloaded pack, is part of the Content Update; the Entry stack's opener `notification-taps.tsx` is in `entries/`, which reads a notification's link mark, so `notifications/` imports no Entry module; and the SLOVO ID screen `account-screen.tsx`, which draws Sync's status line, sits with the other settings screens in `settings/`.
- **The routes import `src` through `@/`.** The Expo Router routes in `apps/mobile/src/app/` import the app's modules as `@/opening` or `@/entries/entry-screen`, not `../../opening`, so a route's imports don't change with its depth. `@/` maps to `apps/mobile/src/` in the app's `tsconfig.json`, which Metro reads, in Jest's `moduleNameMapper` and in dependency-cruiser's resolution. The modules inside `src` keep their relative imports.
- **Files move with `git mv` and keep their names**, so the history follows them and a move changes only import paths. A test stays beside its module.
- **A folder has no `index.ts` barrel.** Each package keeps one public `index.ts`, and the other parts of the workspace import through the package entry points only (dependency-cruiser's `workspace-parts-import-through-the-entry-point`).
- **Domain folders import each other in one direction.** `no-circular` already rejects a cycle between files; a cycle between folders means a module sits in the wrong one, and dependency-cruiser's `domain-folders-import-one-way` (in `.dependency-cruiser.folders.mjs`, run by `pnpm deps`) rejects it as an error. It counts the modules a package ships, not their tests: a test may set its scene up with another domain's module, as `user-state.test.ts` does with the Feed's Cycle.

Not regrouped: `apps/mobile/src/app/` holds the Expo Router routes, whose paths are the app's links. `packages/language-pack` is one build pipeline, `packages/contracts` already has its `edition-strings/`, and `tools/sourcing` is small. Edition content, `docs/` and the Maestro flows are data and documents, whose numbering or ids give their order.

**Two Core entry points.** `index.ts` (`@slovo/core`) exports only what another workspace package or app imports, a test of another package included, plus every Extension Point (ADR 0006). The Core's own tests do not count: they import from the module files, such as `../search/search`, and import `../index` only for what it exports anyway. `testing.ts` (`@slovo/core/testing`) exports the fakes in `fakes/` that the tests of the app and the Language Pack use; only a test or a test-support module imports it, and nothing ships it (dependency-cruiser's `only-tests-import-the-core-testing-entry`).

## Considered Options

- **One folder per component** (`Button/Button.tsx` beside its styles and test): rejected. Styles live in a `StyleSheet.create` in the component's own file (`docs/react-native.md`), and a component's test sits beside it (ADR 0029), so each folder would hold a component and its test, often with its own `index.ts`. The flat list would only move one level down.
- **Folders by layer** (`models/`, `services/`, `hooks/`): rejected. A feature would still be spread over every folder, and the layers of the Core are its modules and the composition on top, not kinds of file.
- **One flat folder**: rejected. With dozens of files in each package, the alphabet decides what sits together.
- **A folder only when a domain has at least two modules**, the rule until 0.8.12: replaced. A single-module domain lay loose at the root in one package and in a folder in another, so the same domain had two addresses.
- **Vertical packages** (a package per domain, such as `@slovo/game`): the owner chose folders on 2026-10-27. The Core's domains share its ports, composition and user state, which a package per domain would have to split or export.
- **`hidden/` for the Mix and Hidden Entries**: rejected. The UI's and the app's folders hold the Mix's chips, its Rarity Floor and the Mix screen, which are not about Hidden Entries, and `mix/` needs fewer moves.
- **`opening`, `opened` and `foreground` in `shell/`**: rejected. Most domains import them and `shell/lifecycle.tsx` imports most domains, so `shell/` would sit in one cycle with thirteen of the app's folders.
- **Counting tests in the folder rule**: rejected. Tests set their scene up across domains, which tangles the Core's folders into one cycle that says nothing about where a module belongs.
