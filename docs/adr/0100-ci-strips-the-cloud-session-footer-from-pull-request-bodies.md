# CI strips the cloud session footer from pull request bodies

Owner decision of 2026-11-09. A cloud session appends a footer such as «_Generated by [Claude Code](…)_» to the body of every pull request it opens. The check "Check the authors and that no AI attribution is left" in `commitlint.yml` then fails, and the PR waits until someone edits the body by hand.

**Decision.** On every pull request, a job of its own, "PR body footer", removes that footer from the body before the attribution check reads it. `scripts/strip-pr-footer.mjs` drops each line that is nothing but "Generated with/by Claude Code" (plain text or a link, in italics or after the robot emoji), with the blank lines and the one `---` separator right before it, and the job writes the cleaned body back to the PR through the API. The check then reads the cleaned body. Any other AI attribution, in the body, the title or a commit, still fails as before.

- **The write token never meets the PR's code.** Only this job has `pull-requests: write`. It checks out the script from the PR's base commit without keeping credentials, installs nothing and runs nothing else; the job "Commit messages", which installs and runs the PR's code, keeps read access.
- **Forks are checked as they are.** A PR from a fork gets a read-only token, so its body is not edited and the check reads it unchanged.
- **A failed strip changes nothing.** When the footer job fails, the check reads the body as it came, so a footer left there still fails it.
- An edit made with `GITHUB_TOKEN` starts no new run, so the cleaned body does not check itself again.

## Considered Options

- **Asking each session to leave the footer out**: not enough alone. The footer still appears, and each time the check fails and the PR waits.
- **Letting the check ignore the footer**: rejected. The squash merge copies the PR body into `main`'s history, so the footer would reach `main`.
- **Editing the body in the job "Commit messages"**: rejected. That job installs and runs the PR's code, which would then run beside a token that can edit the PR.
