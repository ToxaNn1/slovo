# Each Edition publishes its legal pages

The App Store asks every app for a privacy policy at a public address, and an app with Accounts owes its readers terms of use. Each Edition speaks its own language to its own readers, so its legal pages are its own text, like its strings (spec #603, #630). Until 0.8.9 SLOVO had neither the pages nor a place to publish them.

**An Edition's legal pages live in its folder, `editions/<id>/legal/`, one Markdown file per page:** `privacy.md` and `terms.md`, in the Edition's language, each with a front matter naming its title and language. They are Edition content, like the Entries and the strings, so a new Edition writes its own and no Core or UI code holds legal text.

**GitHub Pages publishes them, at the app's domain.** The workflow `pages.yml` runs on every push to `main` that touches `editions/*/legal/**`, the site in `apps/site` (ADR 0071) or itself. The Astro site renders each Edition's pages under `/<id>/` (so `editions/uk/legal/privacy.md` is served at `/uk/privacy`) with its one layout, and the workflow deploys it. The site is served behind the app's custom domain (ADR 0065), one for every Edition with a path per Edition, so the address in the app and in App Store Connect is the product's and not GitHub's; the host stays Pages, and nothing in the backend or the Deployment (ADR 0063) serves a legal page. Cloudflare, in front of the domain, sends only `/<edition>/c/*` and `/.well-known/*` to the Deployment and everything else here (ADR 0125, amending this ADR). A change to a page is live once it merges, with no app build.

**The app builds the addresses from its domain and the Edition id.** The domain is the AppConfig `domain` (ADR 0065), and the contracts' `editionSite` builds each Edition's pages as `https://<domain>/<id>/privacy` and `https://<domain>/<id>/terms`, the same addresses the workflow serves; `apps/site/public/CNAME` names the app's domain, and a test keeps the two equal. The Core's Edition carries them, and About opens them in the browser. The Edition config names neither the domain nor a page address: the addresses are a function of the domain and the id, so writing them by hand made two sources of truth (the workflow and each config) that nobody kept in step, and the domain changes in one field of the AppConfig when it moves. A placeholder domain is refused for a release build by `appReleaseProblems`. The config also names no files: the app bundles no page, it only opens one.

**`edition-folder.ts` names `legal/`.** ADR 0035 makes it the only code that knows where an Edition's files lie. The app doesn't read the pages, it opens their addresses; the site does, and it is Node code, so its content loader lists every Edition and takes each one's pages from `legalPages()`. Until the Astro site the workflow gathered the files with a shell loop over `editions/*/legal`, the one place outside the module that knew a part of an Edition folder's layout; the site replaced the loop.

## Considered Options

- **The pages inside the app**: rejected. The App Store wants a public address it and readers can open without the app, and a change would wait for a build.
- **A separate website repository**: rejected. The pages belong with the Edition they describe, change in the same pull requests as the features they describe, and a second repository is one more thing to keep in step.
- **File names in the config instead of addresses**: rejected. The app has no use for a file it doesn't bundle; it needs the address to open.
- **The full addresses in the config** (the decision until 0.9): dropped. They repeated by hand what the site and the Edition id derive, so a changed site meant editing every Edition and a typo was caught by nobody.
- **One site base for every Edition, as a Core constant** (`LEGAL_SITE`, the decision of #1291, briefly): dropped. The domain is the AppConfig's, not the Core's (ADR 0006, 0065); a constant would name it in code every Edition shares.
- **The legal pages served by the backend**, beside the `/c/<id>` pages: rejected. They are Markdown that Pages already builds and deploys on merge, and a legal text must stay reachable while the Deployment is down or being replaced.
