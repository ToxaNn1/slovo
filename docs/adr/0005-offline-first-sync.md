# Offline-first with last-write-wins sync

The app always reads and writes a local database. When it is online and the user has an Account, it syncs changes with the server in the background. Conflicts are resolved per record by last write wins, and deletions are kept as tombstones so they can't be resurrected by another device. The Streak is derived from synced Active Days, never stored, so merging two devices always gives the right number. Notification times stay per device. One Account (SLOVO ID) spans every Edition, with data partitioned per Edition.

"Last write" is the change the device made last, not the one that reached the server last. Each change carries the time the Core wrote it, and the server keeps a change only when that time is later than the one of the record it keeps; a tie keeps the record kept. A change time later than the server's own time is cut down to it, so a device whose clock runs fast can't win every conflict. A device offline for days keeps the real time of its changes, so they lose to what the reader did since on another device. ADR 0041 says how the server keeps the records and how a device exchanges them.
