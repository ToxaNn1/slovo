## High (from the feed sub-review)

- **H1 `feed/word-of-the-day.ts:138`** — a new day starts a new Cycle while Synonym Rows or Tips are still unseen: the "does the Cycle go on" check counts only Corrections and Idioms, the Feed counts all five kinds. Unseen rows and tips are lost; contradicts ADR 0016, 0051 and the glossary. No test covers it. **confirmed** (code path). Fix: one `cycle.hasUnseen()` over every kind, used by both modules; test first. Details in `core-a-feed.md`.

## Medium

- **M1 `account/account.ts:343-357, 458-463` (tellSignOuts / `untold`)** — the tokens of sign-outs the server has not heard of live only in memory. Scenario: reader signs out offline, closes the app; on the next launch `untold` is empty, `refresh()` has nothing to tell, and the server Session stays valid until it expires. The doc on `signOut` promises "the next `refresh` tells it", which only holds inside one process. **plausible** (needs the backend's Session lifetime to matter). Fix: a `device-only` record of the untold tokens (like `counters.unsent.`), read at `openAccount` and drained by `refresh`; or a server-side TTL short enough to make it moot, written down in ADR 0037.

- **M2 `backend.ts:35`** — `answerOf` maps *any* thrown non-`ORPCError` to `offline`. Scenario: a bug in the shell's fetch adapter or in a response parser throws a `TypeError`; the reader sees «Немає з'єднання», `withRetries` tries three more times with backoff (ADR 0037), and the bug never surfaces in logs or tests. **confirmed** from the code; the masking is a design choice but not written down. Fix: classify only network failures (fetch `TypeError`, `AbortError`) as `offline`; make the rest `unexpected` (not retried) and report them through a port, or at least document the trade-off in ADR 0064.

- **M3 `community-counters/counter-reads.ts:73-91`** — no negative caching: an Entry the backend answers nothing for (or a batch that fails) gets no `counters.read.` record, so every later `lines()` call asks the backend again. Scenario: the Feed asks `lines` for the cards near the current one on every change; one Entry the backend does not know yet (new in the Language Pack, never counted) makes a request per Feed change, all day, for every reader. **plausible** (depends on whether the backend answers zero rows for unknown ids; the contract test in `packages/contracts/src/api/counters.test.ts:155` suggests it echoes the requested ids, which would make this moot — verify). Fix: write a zero record with `readAt` for every requested id missing from the answer; hold back repeat reads after a failed batch (same `heldUntil` idea as `counter-sending.ts`).

Also medium, from the sub-reviews (details there): `entries/` M1 empty `standardEquivalents` representable (`contracts/correction.ts:72` `.min(1)` does not narrow the type; `correction-card.ts:50` throws, `entry-row.ts:125` silently shows the non-standard form); `entries/` M2 `rarity-ceiling.ts:79-82` tells subscribers before `eligibility.publish()` (Mix does the reverse); `entries/` M3 and `feed/` M1 agree: a Hidden Correction stays linked to its Word card (`entries.ts:441-460`, `feed.ts:614-616`) and can become Seen — the glossary says a Hidden Entry never appears in the Feed; `feed/` M2 `feed.ts:532-535` the Feed stops for good when a Cycle id is missing from the Language Pack (`undefined` means both "missing" and "nothing live"); `feed/` M3 `community-word.ts:48-51` network data written to storage unparsed.

## Low

- **L1 `account/account.ts:300`** — `settle(answer as Exclude<A, Unauthorized>)`: an `as` cast where a type guard (`isUnauthorized(answer): answer is Unauthorized`) would narrow. **confirmed.** Fix: make `unauthorized` a type predicate and let TypeScript narrow.
- **L2 `account/account.ts:67-78` `AccountState`** — `inFlight` and `problem` are a free cross-product over the status union: `signed-in` with `inFlight: 'requestCode'`, or `signed-out` with `problem: 'wrong-code'`, are representable though impossible. **confirmed** (type). Fix: put the flight/problem into each member (`signed-out` carries `invalid-email | offline | …`, `code-sent` carries `wrong-code | code-expired | …`), or model `inFlight` as its own state member.
- **L3 `in-turn.ts:50`** — `newestFirst` returns `1` when the keys are equal, so `cmp(a,b) === cmp(b,a) === 1`: an inconsistent comparator. Scenario: two History/Collection items with the same instant and id (a duplicate record after a Sync merge) sort in engine-dependent order. **confirmed** (code), harmless today. Fix: `key(first) < key(second) ? -1 : key(first) > key(second) ? 1 : 0`.
- **L4 `collection-links/share-collection.ts:70,88` and `copy-collection.ts:70,86`** — `schedule: Schedule | undefined` switches between "retry rule" and "tried once"; a test convenience leaks into the production contract (and `random` is required while `schedule` is optional). **confirmed.** Fix: always take `schedule` and give tests an immediate schedule, as `counter-sending.ts` does.
- **L5 `community-counters/counter-sending.ts:103-107` with `counter-deltas.ts:197-201`** — when `unsentAfterSending` meets an out-of-range rest it `continue`s and leaves the record, so the next `sendBatch` sends the same events, the backend counts them again, and `while (await sendBatch())` loops with a request per iteration while the app is in the foreground. Unreachable under the invariant unsent = counted − sent, but nothing guards it. **plausible.** Fix: on out-of-range, delete the record (or `forgetUnsentCounters` for that Entry) and log.
- **L6 `community-counters/counter-reads.ts:77`** — reads bypass `withRetries`; ADR 0064 says "the retry rule lives in the Core" and ADR 0037 calls it the one rule. Possibly intentional for best-effort reads; then say so in the doc comment. **plausible.**
- **L7 `dashboard/correction-types.ts:82-88, 90`** — `markWorkedThrough` runs on *every* Seen Entry (Words included) and each time queries `liveCorrections()` and lists all worked-through records: two storage reads per Seen for a feature about Corrections. The listener's rejected promise is unhandled. **confirmed** (code); perf, not correctness. Fix: ask `entries.get(entryId)` for its kind first, or have the Feed tell Seen with the kind; `void …catch(() => undefined)` in the listener.
- **L8 `dashboard/curated-collections.ts:141-146`** — `refresh()` has no "started" guard (unlike `dashboard.ts:224-233`): a slower, older `railOf()` can overwrite a newer rail when `dayTurned` and a Collections change land close together. **plausible.** Fix: the same `started`/`mine` counter.
- **L9 `dashboard/dashboard.ts:171-173`** — the hero is "revealed" only if `cycle.covers(wordId)`; a Word of the Day outside the Cycle (its Category out of the Mix, Rarity above the Ceiling) stays unrevealed forever and «Розкрити» does nothing visible. **plausible** (depends on how `feed.wordOfTheDay()` chooses; the feed sub-review's L items touch the same seam). Fix: derive revealed from Seen-today in History/Seen records, not from Cycle coverage.
- **L10 `content-update/content-update.ts:134-145, 176-184`** — `openKept` forgets a broken kept pack but leaves `contentUpdate.checkedAt`, so the next check is up to 24 h away and the app runs the bundled pack meanwhile though a newer one is published. **plausible.** Fix: clear the record when forgetting a pack.
- **L11 `analytics/analytics.ts:138`, `counter-deltas.ts:106`** — consent is `=== false`, so a missing `settings.shareCounters` record means "sharing on". Consistent with `settings.ts:92` (default `true`) and ADR 0060/0068, so **not a defect**; noted because the rule is spelled out in three places. Fix (optional): one `isSharing(userState)` helper.
- **L12 tests** — `edition/edition.test.ts:649, 686, 693, 736` assert only `not.toThrow()`; acceptable as schema-acceptance tests but they would pass if `loadEdition` returned garbage. Across my 348 tests the script found none without an `expect`. The sub-reviews list seven more weak tests (`word-card.test.ts:262`, `synonym-row-card.test.ts:137`, `mix.test.ts:615/657`, four in `feed/`).
