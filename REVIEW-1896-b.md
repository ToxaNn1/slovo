## 1. In a grid that stays (`pairsStay`) a pair's pop or drop never plays (medium)

- File: `packages/ui/src/game/PairsGrid.tsx:137-140` (`keyOf`), with `:172-176` (definition `onPress`) and `packages/ui/src/game/useAnswerMotion.ts` (initial `moved`/`shown`).
- Defect: `keyOf` gives the cells of the pair given last a new key (`${place}-${tries}`) "so its look plays anew". But the key and the judged look arrive in the same render: the Definition's `onPress` calls `setGiven(...)` and then `onAnswer`, and `actions.answer` -> `game.answer` runs synchronously up to `changeCurrent(shown)` (`packages/core/src/game/game.ts:965`, `change` tells subscribers at once; with `stays` the Core has already moved on to the next pair with the cell `found`/`missed`). React batches both updates of the press into one render, so the remounted `Cell` mounts with `look` already `right`/`wrong`. `useAnswerMotion` starts such a cell at `moved = 1` with `shown.current = true` ("one shown judged from the start stays put"), so the effect returns early: no pop, no drop, no turn. Without the key change the existing cell would go from `undefined` to judged and animate; the new key is what kills the motion.
- Scenario: `pairsStay` on, Reduce Motion off. Tap «ardent», then its Definition: the pair turns red at once with no `slPop`; a wrong pair appears sunk and turned with no `slDrop`. The component doc promises both.
- Fix: keep the cell's key stable (`String(place)`) and restart the motion from the `tries` count instead, e.g. pass `tries` into `useAnswerMotion` as a replay token (effect keyed on it), or key by `tries` only from the render before the answer lands. Simplest: drop `keyOf` and let `useAnswerMotion` replay when `answer` goes from `undefined` to judged, resetting `shown.current` when the look returns to `undefined`/rest (which happens as the next Word is picked).
- Test: a `PairsGrid` (or `GameRound`) test with `stay` on that renders the grid, presses a Word and its Definition while the parent rerenders with that pair `found` in the same act, and checks the cell's `${testID}-motion` style is mid-pop after advancing fake timers part way (scale != 1), and that under Reduce Motion it is still.
